# Лабораторная работа №5 - Структурные паттерны проектирования

## Цель работы

Изучить структурные паттерны проектирования и применить их для организации взаимодействия классов и объектов на языке Python.

## Описание работы

В ходе лабораторной работы реализованы три структурных паттерна проектирования:

- Proxy (Прокси);
- Adapter (Адаптер);
- Bridge (Мост).

Для каждого паттерна разработан отдельный пример, демонстрирующий его назначение и принцип работы.

## Структура проекта

Исходный код программы находится в директории `lab05/`.

Основные файлы и директории:

- `proxy/` - реализация паттерна Proxy:
  - `proxy.py` - интерфейс базы данных, реальная база данных и прокси с проверкой доступа;
  - `main.py` - демонстрация работы прокси;
- `adapter/` - реализация паттерна Adapter:
  - `adapter.py` - целевой интерфейс Logger, сторонний класс ExternalLogger и адаптер LoggerAdapter;
  - `main.py` - демонстрация работы адаптера;
- `bridge/` - реализация паттерна Bridge:
  - `bridge.py` - интерфейс устройства Device, реализации Monitor и Printer, абстракция Output и её расширения TextOutput и ImageOutput;
  - `main.py` - демонстрация вывода текста и изображений на разные устройства.

## Реализованные паттерны

### Proxy (Прокси)

Паттерн предоставляет объект-заместитель, который контролирует доступ к реальному объекту.

В программе реализован интерфейс `Database`, который определяет метод `query()`. Класс `RealDatabase` представляет реальную базу данных и выполняет запросы.

Класс `DatabaseProxy` выступает в роли прокси. Он проверяет наличие доступа перед выполнением запроса. Если доступ разрешён, запрос передаётся реальной базе данных. В противном случае выводится сообщение об отказе в доступе.

### Adapter (Адаптер)

Паттерн позволяет объектам с несовместимыми интерфейсами работать вместе.

В программе реализован целевой интерфейс `Logger`, который определяет метод `log()`. Класс `ExternalLogger` представляет сторонний класс с методом `log_message()`.

Класс `LoggerAdapter` адаптирует сторонний интерфейс к целевому. Благодаря этому клиент может использовать метод `log()`, который внутри вызывает метод `log_message()` стороннего класса.

### Bridge (Мост)

Паттерн разделяет абстракцию и реализацию на две независимые иерархии, позволяя изменять их независимо друг от друга.

В программе реализован интерфейс `Device` и два конкретных устройства: `Monitor` и `Printer`.

Абстракция `Output` использует объект устройства для вывода данных. Классы `TextOutput` и `ImageOutput` реализуют разные способы вывода информации.

Благодаря этому текст и изображения можно выводить как на монитор, так и на принтер без создания отдельных классов для каждой комбинации.

## Запуск программы

Для работы необходим Python 3.10 или новее.

Дополнительные библиотеки устанавливать не требуется.

Каждый паттерн находится в отдельной директории и имеет собственный файл `main.py`.

Для запуска демонстраций в PyCharm необходимо открыть соответствующий файл `main.py` и нажать кнопку Run:

- `proxy/main.py` - запуск Proxy;
- `adapter/main.py` - запуск Adapter;
- `bridge/main.py` - запуск Bridge.

Каждую демонстрацию можно запустить отдельно.

## Результат

В результате лабораторной работы реализованы три структурных паттерна проектирования на языке Python. Программа демонстрирует контроль доступа к объектам с помощью прокси, взаимодействие несовместимых интерфейсов с помощью адаптера и разделение абстракции и реализации с помощью моста.
