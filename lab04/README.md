# Лабораторная работа №4 - Поведенческие паттерны проектирования

## Цель работы

Изучить поведенческие паттерны проектирования и применить их для организации взаимодействия между объектами на языке Python.

## Описание работы

В ходе лабораторной работы реализованы три поведенческих паттерна проектирования:

- Strategy (Стратегия);
- Chain of Responsibility (Цепочка обязанностей);
- Iterator (Итератор).

Для каждого паттерна разработан отдельный пример, демонстрирующий его назначение и принцип работы.

## Структура проекта

Исходный код программы находится в директории `lab04/`.

Основные файлы и директории:

- `strategy/` - реализация паттерна Strategy:
  - `strategy.py` - интерфейс стратегии, реализации сортировки пузырьком и быстрой сортировки, класс Sorter;
  - `main.py` - демонстрация работы стратегий сортировки;
- `chain/` - реализация паттерна Chain of Responsibility:
  - `chain.py` - интерфейс обработчика, конкретные обработчики A и B, класс Request и перечисление RequestType;
  - `main.py` - демонстрация работы цепочки обработчиков;
- `iterator/` - реализация паттерна Iterator:
  - `iterator.py` - интерфейс итератора и класс ArrayIterator;
  - `main.py` - демонстрация последовательного перебора элементов массива.

## Реализованные паттерны

### Strategy (Стратегия)

Паттерн позволяет определить семейство алгоритмов, инкапсулировать каждый из них и сделать взаимозаменяемыми.

В программе реализован интерфейс `SortingStrategy`, который определяет метод `sort()`. Созданы две конкретные стратегии: `BubbleSortStrategy` для сортировки пузырьком и `QuickSortStrategy` для быстрой сортировки.

Класс `Sorter` выступает в роли контекста. С помощью метода `set_strategy()` можно выбрать необходимый алгоритм сортировки, а метод `sort_array()` запускает выбранную стратегию.

### Chain of Responsibility (Цепочка обязанностей)

Паттерн позволяет передавать запросы последовательно по цепочке обработчиков, пока один из них не сможет обработать запрос.

В программе реализован интерфейс `Handler`, определяющий методы `handle_request()` и `set_next_handler()`.

Созданы два конкретных обработчика: `ConcreteHandlerA` и `ConcreteHandlerB`. Первый обрабатывает запросы типа `TYPE_A`, второй - запросы типа `TYPE_B`.

Класс `Request` представляет запрос, а перечисление `RequestType` определяет его тип. Обработчики связаны в цепочку, благодаря чему запрос передаётся следующему обработчику, если текущий не может его обработать.

### Iterator (Итератор)

Паттерн предоставляет способ последовательного доступа к элементам коллекции независимо от её внутренней реализации.

В программе реализован интерфейс `Iterator`, который определяет методы `has_next()` и `next()`.

Класс `ArrayIterator` является конкретной реализацией итератора. Он хранит список элементов и текущую позицию. Метод `has_next()` проверяет наличие следующего элемента, а метод `next()` возвращает следующий элемент и перемещает позицию.

Если элементы закончились, генерируется исключение `IndexError`.

## Запуск программы

Для работы необходим Python 3.10 или новее.

Дополнительные библиотеки устанавливать не требуется.

Каждый паттерн находится в отдельной директории и имеет собственный файл `main.py`.

Для запуска демонстраций в PyCharm необходимо открыть соответствующий файл `main.py` и нажать кнопку Run:

- `strategy/main.py` - запуск Strategy;
- `chain/main.py` - запуск Chain of Responsibility;
- `iterator/main.py` - запуск Iterator.

Каждую демонстрацию можно запустить отдельно.

## Результат

В результате лабораторной работы реализованы три поведенческих паттерна проектирования на языке Python. Программа демонстрирует использование взаимозаменяемых алгоритмов сортировки, передачу запросов по цепочке обработчиков и последовательный доступ к элементам коллекции с помощью итератора.
